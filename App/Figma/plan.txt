2.2 Database (Prisma + PostgreSQL)
model User {
  id              String    @id @default(uuid())
  phone           String    @unique
  name            String?
  city            String?
  birthday        DateTime?
  gender          String?
  pronouns        String?
  socialType      String?   // introvert, extrovert, ambivert
  interests       String[]  // chill activities
  hobbies         String[]  // niche hobbies
  lookingFor      String[]  // mentorship, friendship, etc.
  linkedinUrl     String?
  instagramUrl    String?
  isVerified      Boolean   @default(false)
  profileComplete Int       @default(0)
  avatarUrl       String?
  createdAt       DateTime  @default(now())
  updatedAt       DateTime  @updatedAt
}

model Conversation {
  id        String   @id @default(uuid())
  users     User[]
  messages  Message[]
  createdAt DateTime @default(now())
}

model Message {
  id             String      @id @default(uuid())
  conversationId String
  conversation   Conversation @relation(fields: [conversationId], references: [id])
  senderId       String
  sender         User        @relation(fields: [senderId], references: [id])
  content        String
  read           Boolean     @default(false)
  createdAt      DateTime    @default(now())
}

model QuizAnswer {
  id        String @id @default(uuid())
  userId    String
  user      User   @relation(fields: [userId], references: [id])
  question  String
  answer    String
  category  String // rapid_fire, would_you_rather, opinion
}

model Match {
  id           String   @id @default(uuid())
  user1Id      String
  user2Id      String
  score        Float    // compatibility score
  createdAt    DateTime @default(now())
}

Key Architectural Decisions
1. Separate apps, not nested - Express handles heavy lifting (WebSocket, AI inference later), Next.js handles SEO/admin
2. Shared types - Single source of truth, both frontends import same interfaces
3. NativeWind + Tailwind - Same design tokens across web and mobile
4. Prisma - Type-safe DB queries, auto-generated types for shared package
5. Turborepo - Parallel builds, caching, task orchestration
Want me to start implementing? I'd begin with Phase 1 (monorepo setup) and Phase 2 (API server with Prisma schema), then move to the mobile onboarding screens since those have complete Figma designs.
